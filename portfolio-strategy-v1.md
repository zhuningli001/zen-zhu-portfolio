# Portfolio Strategy v1 — Ningli Zhu / Zen-Zhu Studio

## 1. Core Direction

This portfolio should not be built as a traditional visual design archive. It should be built as a professional identity system for a senior hybrid designer working across AI-native UX, design technology, complex systems, design strategy, brand/web experiences, and cultural projects.

The central message:

> I turn complex design problems into structured, aesthetic, shippable, reusable, and AI-ready systems.

Chinese working version:

> 我把复杂问题转化为有审美、有结构、可交付、可复用，并能被 AI 理解和协作的系统；同时持续探索科技设计、艺术文化和未来体验之间的连接。

The site should prove that Ningli can:

- Understand ambiguous and complex design problems.
- Structure information, workflows, and product logic.
- Build aesthetic and consistent visual systems.
- Work across AI, UX, brand, web, marketing, and culture.
- Deliver outcomes independently or as a senior collaborator.
- Connect technology, aesthetics, and cultural imagination into practical design systems.

## 2. Positioning

## 4. Site Strategy

Build the website as a public design knowledge system, not only a portfolio.

The site should have four layers:

1. Professional identity: Senior UX / AI UX / Design Strategist.
2. Evidence: projects, systems, frameworks, process, shipped work.
3. Studio practice: independent projects, cultural work, direct client collaboration.
4. Research layer: AI-native design systems, design knowledge, agent workflows, design infrastructure.

The current public version can now lead with selected AI / YIOne / CXD / Momcozy materials, while using public cultural and brand projects as supporting evidence. Sensitive internal details should still be cropped, abstracted, or reframed as systems and process.

## 5. Recommended Information Architecture

Recommended lightweight structure:

1. `Home`
2. `Work`
3. `Notes`
4. `About`
5. `Contact`

`Studio` should appear as a section inside `About` or `Home`, not as a separate top-level page in v0.1.

`Notes` should be used instead of `Research` for the first version. It feels lighter, more personal, and easier to maintain, while still allowing research-led writing inside.

## 7. Case Study Template

Use a consistent structure for public case studies:

1. Context
   - What was the project?
   - Who was it for?
   - What was the challenge?

2. Role
   - What did Ningli own?
   - What did she collaborate on?
   - What was outside her scope?

3. Problem
   - What made the project complex?
   - What constraints existed?
   - What needed to be clarified?

4. System
   - Information architecture.
   - Design language.
   - Content model.
   - Component or module logic.
   - Brand rules or visual patterns.

5. Process
   - Research.
   - Mapping.
   - Prototyping.
   - Iteration.
   - Delivery.

6. Outcome
   - Final deliverables.
   - Shipped or implemented status.
   - Business, user, brand, or organizational value.

7. Reflection
   - What was learned?
   - What pattern can be reused?
   - How this connects to AI-native design knowledge.

## 9. Visual Direction

The visual language should be:

- Minimal.
- Editorial.
- Systematic.
- High-end but not decorative.
- Typography-led.
- Grid-based.
- Calm, precise, and international.

Avoid:

- Behance-style decoration.
- Overly colorful gradients.
- Excessive animation.
- Generic AI-glow aesthetics.
- Too much agency-style marketing language.

Useful references already mentioned:

- Nuevo.Tokyo: for research-led studio positioning.
- Cynergy Ventures: for cross-cultural bridge and institutional clarity.
- Ryo Lu / Cursor design direction: for product-design and design-engineering ambition.

The site should borrow the clarity and systems thinking of these references, not their surface style.
